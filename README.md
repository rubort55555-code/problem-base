# База проблем плагина

Единая база проблем: коллеги сообщают о проблемах через общий GPT (или форму GitHub), GitHub Action превращает каждую в markdown-заметку, заметки открываются в Obsidian и доступны любой LLM для анализа.

```
Коллега → GPT / форма → GitHub Issue → Action → issues/P-0042 ….md → Obsidian + LLM
```

## Что где лежит

| Путь | Назначение |
|---|---|
| `issues/` | Заметки проблем (создаются автоматически) |
| `issues/attachments/` | Скриншоты |
| `dashboard.md` | Дашборд Dataview |
| `templates/issue.md` | Шаблон для заметки, созданной вручную в Obsidian |
| `.github/ISSUE_TEMPLATE/problem.yml` | Форма проблемы на GitHub |
| `.github/workflows/issue-to-md.yml` + `scripts/issue_to_md.py` | Превращение Issue в `.md` |
| `gpt/` | Инструкция и схема Action для Custom GPT |

## Настройка (один раз)

1. **Репозиторий.** Создайте на GitHub **приватный** репозиторий, загрузите туда содержимое этой папки. Settings → Actions → General → Workflow permissions → **Read and write permissions**.
2. **Токен для GPT.** GitHub → Settings → Developer settings → Fine-grained tokens. Доступ только к этому репозиторию, права: **Issues: Read and write**, Metadata: Read. Сохраните токен.
3. **Custom GPT.** ChatGPT → Explore GPTs → Create. В Instructions вставьте текст из `gpt/instructions.md`. В Actions: Create new action → вставьте `gpt/openapi.yaml` (заранее замените `OWNER/REPO` на свои), Authentication → API Key → Bearer → ваш токен. Поделитесь GPT с коллегами по ссылке.
4. **Obsidian у каждого.** Склонировать репозиторий, открыть папку как vault. Плагины: **Obsidian Git** (автоматические pull/push каждые 5 минут) и **Dataview**. В Settings → Files and links → «Default location for new attachments» укажите `issues/attachments`.

## Как пользоваться

- **Сообщить о проблеме:** написать общему GPT, что случилось, или попросить «выгрузи проблему». Он сначала ищет дубли, потом создаёт Issue.
- **Добавить скриншоты:** открыть заметку в Obsidian, вставить картинку (Ctrl+V) ниже строки `<!-- ДОПОЛНЕНИЯ … -->`, Obsidian Git отправит изменения.
- **Всё, что написано ниже этой строки, скрипт не перезаписывает.** Там же причина и решение.

## Анализ и правки через LLM

Клонируйте репозиторий и работайте в нём с Claude Code (или другой LLM с доступом к файлам): поиск повторов, объединение дублей, заполнение «Причина»/«Решение», сводки. Правила для LLM лежат в `CLAUDE.md`. Изменения коммитятся в репозиторий и приходят всем через Obsidian Git.

## Ограничения (стоит знать)

- Токен в GPT общий, поэтому автор определяется по полю «Автор», которое GPT спрашивает у человека.
- GPT не видит картинки из чата в базе: скриншоты добавляются только вручную.
- Обычные личные чаты GPT к базе не подключаются, работает только общий Custom GPT.
- Править статус и описание можно в `.md`; если вы меняете заголовок или описание в самом Issue, скрипт обновит эти части заметки, а статус, теги и всё ниже маркера сохранит.
