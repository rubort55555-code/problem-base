# Правила работы LLM с базой проблем

Репозиторий — база проблем плагина. Каждая проблема это `issues/P-NNNN <название>.md`.

## Структура заметки
- Frontmatter: `id, title, status, severity, plugin_version, os, reporter, source, tags, created, updated, issue_url`. Допустимые `status`: `open`, `in_progress`, `closed`.
- Часть выше строки `<!-- ДОПОЛНЕНИЯ … -->` генерируется из GitHub Issue и может быть перезаписана. **Не редактируй её**, правь через Issue.
- Часть ниже маркера (`Причина`, `Решение`, скриншоты, комментарии) — рабочая зона, её можно править свободно.

## Что можно делать
- Находить дубли и повторяющиеся причины, добавлять в frontmatter `related: ["P-0012"]`.
- Заполнять «Причина» и «Решение» по накопленным данным; ставить `status` и теги.
- Строить сводки (по версиям, ОС, тегам) в отдельных файлах `reports/`.

## Чего не делать
- Не удалять и не переименовывать файлы в `issues/`.
- Не менять `id`, `issue_url`, `created`.
- Не выдумывать причины: если данных мало, пиши «гипотеза» и что нужно уточнить.
- Не вставлять в заметки пароли, токены и персональные данные.
